## 1. The assignment and its non-code part (short)

The user is interviewing for a TPM position (technical project manager, industrial
automation). Homework: `task-description.md`.

- **Legend:** 3 mining haul trucks (scale to 60 units within 12 months), onboard controller over
  Modbus, telematics gateway with SIM and private APN, operator link at L2/L3, solution runs in
  an on-prem Kubernetes, logging + Active Directory + SIEM mandatory. Sensor -> dashboard latency
  <= 30 s, 12 months retention, 99% availability 7:00-23:00, coverage gaps of 40 min and longer,
  no data loss allowed, <= 4.5 FTE, pilot by end of quarter. 40 telemetry registers.
- **Deliverable document:** assumptions and open questions, DFD (2.1), L3 scheme + firewall rule
  table (2.2), architecture diagram (2.3), roadmap with top-5 risks (2.4), effort estimate by role
  and stage with FTE profile and MVP scope (2.5), dashboard prototype (2.6 - the only working
  artifact, i.e. this repository), what is out of pilot scope.
- **Where the non-code artifacts live:**
  - `result/` - document drafts: `0-допущения.md` (solution summary: L3 link via IPsec, gateway
    batches readings per 5 s, backlog after outages resent via a separate low-priority topic,
    MQTT broker and TSDB outside the cluster), `4-roadmap.md` (mermaid Gantt, checkpoints, risks,
    trade-offs), `5-estimation.md` (empty), `dfd.drawio`.
  - `prep/00-10` - interview study materials (networking L1-L3, capacity math, industrial data,
    architecture, corporate integrations, notations, project management, estimation, management

  - `docs/c4/workspace.dsl` - Structurizr C4. `job-description.txt` - the vacancy.
- The prototype is a demo stand: no real trucks or backend, telemetry is generated by a simulator

## 6. Monitoring (stage 4) - how it works

```
MonitoringPane (scroll root + ScrollRootContext)
  selectedVehicleId === null -> list/VehicleList
  otherwise                  -> vehicle/VehiclePage key=vehicleId
                                  VehicleHeader (vehicle info, summary, EventStats)
                                  charts/ComparativeCharts (4 SVG charts)
                                  timeseries/SeriesCanvas -> SeriesRow x 28 (uPlot)
```

- **List** (`list/`): `use-fleet.ts` - order (alarms, warnings, grey, green; then side number) and
  fleet summary; `VehicleCard` - severity stripe, 7 metrics, grey card shows last transmission
  and driver phone. Hiding metrics by width - `monitoring.css` (container queries by `data-rank`).
  `refresh.ts`: cards and order refresh **once per second** via `startTransition` (at 4 Hz with
  60 vehicles tasks took 100+ ms). `VehicleList` refetches the vehicle dictionary when the snapshot
  has unknown vehicle ids.
- **Point values** (`data/snapshot-values.ts`): snapshot physical values + derived via contract
  functions; `STALE` treated as good (see pitfalls); `pointContext` (stopped = 1 s);
  `severitiesOf` - traffic light via `metricSeverities`.
- **Series** (`timeseries/use-vehicle-series.ts` + `series-buffer.ts`): one history request per
  vehicle and period (window anchored at page open / period change, stored together with the
  period), then `SeriesBuffer` is extended from the vehicle's snapshots; live values are folded
  into buckets of the same step using the metric's aggregation, window slides. Gap > 60 s between
  buffer edge and snapshot -> history refetch. All 28 metrics (coordinates excluded) are passed
  in `metrics` explicitly. The same buffer feeds the comparative charts, so monitor values match
  by construction.
- **Canvas**: `SeriesRow` is virtualized (`useInView`, 480 px margin), fixed height 214 px;
  `uplot-chart.ts` - avg line, min/max band (`bands`), norm zones in `drawClear`, monitor in `draw`,
  cursor `sync` keyed by vehicle, click -> `setMonitorTs`, hover value written directly to DOM.
  Data via `setData` on buffer version, monitor via `redraw` only. Counters (`kind === 'counter'`)
  shown as increase over the period. Display unit - `unit-prefs.ts` (survives virtualization).
  Canvas colors - `theme-colors.ts` (CSS variables, re-read on `MutationObserver` of `html`).
- **Autoscroll** on `focusMetric` - in `SeriesCanvas`; focus is cleared inside the rAF after scrolling.
- **Charts** (`charts/`): bars in percent SVG coordinates with `preserveAspectRatio="none"`, labels in
  HTML, colors via `fill-sev-*` classes. `chart-math.ts`: `normativeZones` (context-free rule),
  `rangeWithZones`, `redlineScale` ("percent to red zone"), `gearLabel`.
- **Header**: `use-sticky-summary.ts` keeps the previous response (window moves every 5 s);
  "no data for period" -> explanation + big driver phone, charts and canvas replaced by one
  EmptyState. `EventStats`: last occurrence time fetched from `/api/events` on click.

## 7. Conventions (do not break)

1. Norms, traffic light, derived metrics, formatting - only from `@ra/contracts`. No thresholds
   in components; magic numbers live in `config.ts` or dictionaries (commented local UI constants ok).
2. TS strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`: pass optional fields as
   `...(cond ? { x } : {})`, check indexed access.
3. Imports with `.js` extension, alias `@/` -> `apps/web/src`. Named exports.
4. Comments and UI strings in Russian; identifiers and codes in English. Time in the site timezone
   (`shared/format/time.ts`), unit always next to value.
5. All frontend requests go through `shared/api`. Telemetry never goes into zustand or React state.
6. Styling only via design-system tokens (glass, teal/cinnabar, `sev-*`); right-pane responsiveness
   via container queries, not media queries.
7. Biome `useExhaustiveDependencies`: a "version" dependency for mutable stores gets a
   `biome-ignore` with a reason; unused suppressions are also errors.
8. Tests are `*.test.ts` next to the code, pure logic only (components are not tested).

## 8. Pitfalls (already hit)

- **Contracts come from dist.** Web and server import `@ra/contracts` from `dist`: after editing
  contracts run `pnpm --filter @ra/contracts build`, otherwise web tsc misses new exports.
- **`GET /api/telemetry/series` without `metrics`** returns only traffic-light metrics.
- **`STALE` on 0.2 Hz metrics** (fuel, cargo, axles, body angle) = "between polls, value is the last
  poll". Server history does not count them in `count`. Without the override the card showed a dash
  4 seconds out of 5.
- **Summary** `eventStats` has only `firstAt`; last occurrence comes from `/api/events`.
- **Vehicle dictionary is cached forever**; it goes stale when the fleet changes not via `useSetSim`
  (another client, direct POST).
- **`useSyncExternalStore` renders synchronously**: large lists subscribed to ticks block frames -
  throttle + `startTransition`.
- **An effect that changes its own dependency** cancels its scheduled rAF in cleanup.
- **Period change**: window state set in an effect causes an extra request with the old edge and its
  abort - set it during render.
- **Theme** is applied by an effect in the root, which runs after children's effects: read colors on
  the actual `data-theme` attribute change, not from the store value.
- **Browser pane caps rAF at ~16 fps** even on an idle page: do not measure FPS there. Measure long
  tasks (`PerformanceObserver`), tick task time (wrap `snapshotStore.applyTicks`), timer rate.
  Store is reachable from the console in dev: `await import('/src/shared/store/index.ts')`,
  snapshot store: `'/src/shared/ws/index.ts'`.
- **Map flies to the track** only when the vehicle was selected on the right (`selection-origin.ts`).
- **zsh in the Bash tool**: `echo ===X` breaks (`=` expansion), `--include=*.ts` must be quoted;
  `cd` persists between calls - use absolute paths, including for biome.
- **After `biome check --write`** reformatted files must be re-read before `Edit`.
- Perf check "60 vehicles x60": POST `/api/sim`, wait for `running: true`, measure list and vehicle
  page separately, then restore 3 vehicles and x1.
