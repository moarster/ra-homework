## 4. Monitoring  - how it works

```
MonitoringPane (scroll root + ScrollRootContext)
  selectedVehicleId === null -> list/VehicleList
  otherwise                  -> vehicle/VehiclePage key=vehicleId
                                  VehicleHeader (vehicle info, summary, EventStats)
                                  charts/ComparativeCharts (4 SVG charts)
                                  timeseries/SeriesCanvas -> SeriesRow x 28 (uPlot)
```

- **List** (`list/`): `use-fleet.ts` - order (alarms, warnings, grey, green; then side number) and
  fleet summary; `VehicleCard` - severity stripe, 7 metrics, grey card shows last transmission
  and driver phone. Each metric is a translucent bordered tile (136 px first, 132 px others):
  icon 24 px + value (`ValueDisplay` size `xl`, 22 px), no visible name. Hover softly raises the
  tile background and shows `Tooltip` with `metric.name` (plus vehicle status on the first tile).
  The tile has `pointer-events-auto` for the tooltip, so it calls `selectVehicle` on click itself
  (the card button under it no longer receives the click). Hiding metrics by width -
  `monitoring.css` (container queries by `data-rank`; only rank 1 fits the 360 px minimum;
  thresholds are measured on the live layout, not hand-derived - see pitfalls).
  `refresh.ts`: cards and order refresh **once per second** via `startTransition` (at 4 Hz with
  60 vehicles tasks took 100+ ms). `VehicleList` refetches the vehicle dictionary when the snapshot
  has unknown vehicle ids.
- **Point values** (`data/snapshot-values.ts`): snapshot physical values + derived via contract
  functions; `STALE` treated as good (see pitfalls); `pointContext` (stopped = 1 s);
  `severitiesOf` - traffic light via `metricSeverities`.
- **Series** (`timeseries/use-vehicle-series.ts` + `series-buffer.ts`): one history request per
  vehicle and period (window anchored at page open / period change, stored together with the
  period), then `SeriesBuffer` is extended from the vehicle's snapshots; live values are folded
  into buckets of the same step using the metric's aggregation, window slides. Gap > 60 s between
  buffer edge and snapshot -> history refetch. All 28 metrics (coordinates excluded) are passed
  in `metrics` explicitly. The same buffer feeds the comparative charts, so monitor values match
  by construction.
- **Canvas**: `SeriesRow` is virtualized (`useInView`, 480 px margin), fixed height 214 px;
  `uplot-chart.ts` - avg line, min/max band (`bands`), norm zones in `drawClear`, monitor in `draw`,
  cursor `sync` keyed by vehicle, click -> `setMonitorTs`, hover value written directly to DOM.
  Data via `setData` on buffer version, monitor via `redraw` only. Counters (`kind === 'counter'`)
  shown as increase over the period. Display unit - `unit-prefs.ts` (survives virtualization).
  Canvas colors - `theme-colors.ts` (CSS variables, re-read on `MutationObserver` of `html`).
- **Autoscroll** on `focusMetric` - in `SeriesCanvas`; focus is cleared inside the rAF after scrolling.
- **Charts** (`charts/`): bars in percent SVG coordinates with `preserveAspectRatio="none"`, labels in
  HTML, colors via `fill-sev-*` classes. `chart-math.ts`: `normativeZones` (context-free rule),
  `rangeWithZones`, `redlineScale` ("percent to red zone"), `gearLabel`.
- **Header**: `use-sticky-summary.ts` keeps the previous response (window moves every 5 s);
  "no data for period" -> explanation + big driver phone, charts and canvas replaced by one
  EmptyState. `EventStats`: last occurrence time fetched from `/api/events` on click.

## 4a. Telemetry simulator - how it works

Spec: `prompts/5_PROMPT_SIMULATOR.md`. Files in `apps/server/src/sim/simulator/`:

| File | Contents |
|---|---|
| `telemetry-simulator.ts` | `TelemetrySource` impl; options `{scenarios, route}` for tests; `scenarioStarts()`, `tripsByVehicle()`. Module comment has the "why TS, not Python" rationale |
| `vehicle.ts` | `VehicleSim`: trip FSM, corridor motion, channels, load/fuel, scenarios, bits, frame, outage buffer |
| `params.ts` | Mode target table, rpm->pressure curves, tau, noise/drift amplitudes, cycle and scenario params. Every deviation from the spec numbers is commented there |
| `chaos-profile.ts` | `chaosProfile(level)` - the only place with per-level numbers; intensity and overlap come from `CHAOS_LEVELS` |
| `route-geometry.ts` | Polyline in local meters, vertex-averaged normals, `positionAt(s, lateral)`, `halfWidthAt`, `distanceToRoute` (tests) |
| `flags.ts` | `FlagDebouncer`: bits from contract norms (compiled rules), raise after 5 s, clear after 15 s |
| `scenarios.ts` | Scenario enum, weights (mandatory x2), triggers (mode binding) |
| `shift.ts` | Site UTC offset via Intl, break anchors 02/08/14/20 local |

- **Model:** value -> mode target with tau; published = value x (1 + drift + noise), both OU processes
  with the chaos gain inside the increment (no steps on level change). Oil pressure is a function of
  current rpm (not lagged), transmission pressure too (12.4 bar accumulator with engine off).
- **Chaos:** gains apply immediately; `vehicleSpread`, `targetBias`, `brakeBias`, corridor and GNSS
  amplitude blend per vehicle over 2-5 min. `targetBias` shifts the mode target (not the current
  value) toward the yellow boundary, only in `worseDirection`.
- **Cycle:** LOADING -> HAULING -> UNLOADING -> (break/refuel) -> RETURNING -> (break/refuel/idle/
  queue) -> LOADING. Min trip 24 min (queue at the excavator). Breaks happen at the next stop, the
  truck parks where it stands (no teleport). Stop point 20-30 m back from the route end.
- **Outage:** live mode buffers every second and hands the buffer out when the link returns; in
  history mode an outage is a permanent hole (the engine writes history directly, no backfill path).
- **Determinism:** one `mulberry32` per vehicle seeded with `seed + hash(id)`; vehicle state is
  initialized lazily on its first `advance`, so vehicles added later start from their history time.

## 5. Conventions (do not break)

1. Norms, traffic light, derived metrics, formatting - only from `@ra/contracts`. No thresholds
   in components; magic numbers live in `config.ts` or dictionaries (commented local UI constants ok).
2. TS strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`: pass optional fields as
   `...(cond ? { x } : {})`, check indexed access.
3. Imports with `.js` extension, alias `@/` -> `apps/web/src`. Named exports.
4. Comments and UI strings in Russian; identifiers and codes in English. Time in the site timezone
   (`shared/format/time.ts`), unit always next to value.
5. All frontend requests go through `shared/api`. Telemetry never goes into zustand or React state.
6. Styling only via design-system tokens (glass, teal/cinnabar, `sev-*`); right-pane responsiveness
   via container queries, not media queries.
7. Biome `useExhaustiveDependencies`: a "version" dependency for mutable stores gets a
   `biome-ignore` with a reason; unused suppressions are also errors.
8. Tests are `*.test.ts` next to the code, pure logic only (components are not tested).

## 6. Pitfalls (already hit)

- **Contracts come from dist.** Web and server import `@ra/contracts` from `dist`: after editing
  contracts run `pnpm --filter @ra/contracts build`, otherwise web tsc misses new exports.
- **`GET /api/telemetry/series` without `metrics`** returns only traffic-light metrics.
- **`STALE` on 0.2 Hz metrics** (fuel, cargo, axles, body angle) = "between polls, value is the last
  poll". Server history does not count them in `count`. Without the override the card showed a dash
  4 seconds out of 5.
- **Summary** `eventStats` has only `firstAt`; last occurrence comes from `/api/events`.
- **Vehicle dictionary is cached forever**; it goes stale when the fleet changes not via `useSetSim`
  (another client, direct POST).
- **`useSyncExternalStore` renders synchronously**: large lists subscribed to ticks block frames -
  throttle + `startTransition`.
- **An effect that changes its own dependency** cancels its scheduled rAF in cleanup.
- **Period change**: window state set in an effect causes an extra request with the old edge and its
  abort - set it during render.
- **Theme** is applied by an effect in the root, which runs after children's effects: read colors on
  the actual `data-theme` attribute change, not from the store value.
- **Browser pane caps rAF at ~16 fps** even on an idle page: do not measure FPS there. Measure long
  tasks (`PerformanceObserver`), tick task time (wrap `snapshotStore.applyTicks`), timer rate.
  Store is reachable from the console in dev: `await import('/src/shared/store/index.ts')`,
  snapshot store: `'/src/shared/ws/index.ts'`.
- **Map flies to the track** only when the vehicle was selected on the right (`selection-origin.ts`).
- **A button inside a `setPointerCapture` container swallows clicks.** `SplitLayout`'s collapse
  buttons sit inside the separator `div` that captures the pointer on `onPointerDown` to support
  dragging; a click on the buttons bubbles `pointerdown` to the separator first, the separator
  captures the pointer, and the resulting click retargets to the separator instead of the button.
  Fix: `stopPropagation` on `pointerdown` at the buttons' wrapper, before it reaches the separator.
- **`monitoring.css` container-query thresholds must be measured, not derived by hand.** Card
  metric width does not shrink text to fit; if a rank is shown (`display:flex`) before the
  container is wide enough, the row's `overflow-hidden` silently clips it instead of erroring.
  After changing `VehicleCard` metric sizing, force every `.vehicle-card-metric` to
  `style.display='flex'` in the console and read `getBoundingClientRect()` to get the real
  right edge of each rank, then set the threshold so the container has room for it plus the
  trailing gap/chevron/padding (in this codebase: each same-width rank adds exactly
  `width + gap` to the previous threshold).
- **zsh in the Bash tool**: `echo ===X` breaks (`=` expansion), `--include=*.ts` must be quoted;
  `cd` persists between calls - use absolute paths, including for biome.
- **After `biome check --write`** reformatted files must be re-read before `Edit`.
- Perf check "60 vehicles x60": POST `/api/sim`, wait for `running: true`, measure list and vehicle
  page separately, then restore 3 vehicles and x1.
- **The event detector opens a flag event on the first frame a bit is set** - any bit source must
  debounce itself (the simulator does, `flags.ts`).
- **Norm contexts that bite a generator:** transmission pressure has no engine-off context (0 bar =
  red parked truck); oil pressure switches zones at exactly 1000 rpm (never park rpm there); cargo
  and axle norms apply only to a loaded moving truck; mode targets from the spec table sat on yellow
  boundaries (coolant 96, oil 110, return speed 26-32).
- **`clock.advance(n)` overstates step cost** (3600 x 60 vehicles takes ~1.1 s even with the old
  stub). Judge "no lag at x60" by the real clock: `engine.health().clock.lagSeconds`.
- **Port 3001 may be taken by another chat's `rusal-server`** running the same folder (tsx watch
  picks up edits). Read its state, do not POST `/api/sim` to it.
- **`pkill -f "<pattern>"` in the Bash tool kills its own shell** (the pattern is in the command
  line; exit 144). Use a bracket trick: `pkill -f "apps/server/dis[t]/index.js"`.
- **Virtual time is integer:** at x1 a 60 s window reads 59-61 steps, so a pure 2% lag criterion
  fails low speeds by rounding. The benchmark allows at least 2 steps.
- **Esri World Imagery forbids tile export** (`exportTilesAllowed: false` in `MapServer?f=json`):
  only single `export` images are allowed for offline use.
- **MapLibre tile requests are not visible** in the Browser pane network log (worker fetch);
  test tile failure by patching `window.fetch` for `arcgisonline` and zooming to new tiles.
- **A tile timeout of 8 s gave a false offline switch** on a loaded machine; now 12 s.
- **Biome checks HTML in `apps/web/public`**: a temporary catalog page there breaks `pnpm check`.
- **The Browser pane cannot screenshot `file://` pages**: put temporary pages under `apps/web/public`
  and open them through the Vite server, then delete them.
- **Ref callbacks that set state must be stable** (`useCallback`/`useMemo`). A new ref function per
  render makes React 19 detach (null) and attach (node) on every commit; both set state, so a parent
  re-rendering per tick loops into "Maximum update depth exceeded". Hit in `Tooltip` (composed ref)
  under the map controls at 60 vehicles x300; `MapPane` container ref fixed the same way.
- **Rebuilding contracts restarts the dev server** (tsx watch sees dist): a POST `/api/sim` made
  before the build is lost - check `vehicles` in client stats before trusting a measurement.
- **To read a full React error stack** in the Browser pane, patch `console.error` to collect
  `arg.stack`, then press the error boundary retry button.
- **`pnpm deploy --prod` run inside the workspace marks `node_modules` as a production install**:
  afterwards every `pnpm check`/`pnpm test` fails in the deps status check
  (`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`, it wants `pnpm install --production`). Deploy only
  inside Docker; if run locally, restore with `CI=true pnpm install --frozen-lockfile` (stop dev
  servers first).
