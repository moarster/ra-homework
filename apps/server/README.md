# apps/server - бэкенд дашборда

Fastify-сервер: хранит телеметрию парка в памяти, отдает ее фронтенду в компактном виде, ведет
журнал событий, транслирует поток по websocket и управляет параметрами симуляции.

Контракты API описаны в `SPEC.md` (разделы 5-9), предметная область - в `CONTEXT.md`.
Все справочники, нормативы, расчет светофора и zod-схемы берутся из `@ra/contracts`
и здесь не дублируются.

## Запуск

```bash
pnpm --filter @ra/server dev     # tsx watch, порт 3001
pnpm --filter @ra/server test    # vitest
pnpm --filter @ra/server check   # tsc --noEmit
```

Переменные окружения (все необязательные):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | 3001 | Порт |
| `HOST` | 0.0.0.0 | Адрес |
| `LOG_LEVEL` | debug (info в production) | Уровень логирования pino |
| `LOG_PRETTY` | 1 | Красивый вывод логов; `0` - строгий JSON |
| `SIM_SEED` | 20260913 | Seed симуляции: одинаковый seed дает одинаковый прогон |
| `SIM_VEHICLES` | 3 | Машин на старте (3..60) |
| `SIM_HISTORY_SECONDS` | 43200 | Глубина предыстории (12 часов) |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Разрешенные источники |

## Проверка вручную

```bash
./scripts/api-examples.sh                      # все запросы REST, коды и размеры ответов
./scripts/api-examples.sh http://localhost:3001 1   # то же с телами ответов
node scripts/ws-probe.mjs ws://localhost:3001/ws 10 # частота тиков и точки позиции
```

Примеры запросов для IntelliJ HTTP Client и REST Client - в `requests.http`.

## Устройство

```
src/
  index.ts            точка входа, graceful shutdown
  app.ts              сборка Fastify: логи, CORS, маршруты, websocket
  env.ts              переменные окружения
  errors.ts           единый формат ошибок { error: { code, message } }
  server-config.ts    числовые правила самого сервера (не контракт системы)
  sim/
    clock.ts          виртуальное время, скорость 1..60, учет отставания
    source.ts         интерфейс TelemetrySource - граница сервера и физики
    stub-source.ts    заглушка этапа 1: цикл рейса, коридор, сценарии, провалы связи
    stub-params.ts    числа заглушки (заменяется целиком на этапе 5)
    random.ts         детерминированный ГПСЧ и сглаживание
    engine.ts         движок: часы + источник + хранилище + детектор + websocket
  store/
    ring-buffer.ts    кольцевые буферы трех уровней на типизированных массивах
    position-store.ts кольцо позиций с шагом 1 с за 24 часа
    tiered-store.ts   хранилище парка и последнее состояние машин
    query.ts          выбор уровня, досворачивание до maxPoints, серии и треки
    stored-metrics.ts состав показателей хранилища (23 физических + 7 производных)
  events/
    detector.ts       свертка битов и выходов за нормативы в события
    journal.ts        журнал событий за 24 часа с индексом по машине
  summary/summary.ts  сводка по машине за период
  routes/             REST API
  ws/hub.ts           websocket: hello, тики, события, дозаливка
```

### Что где решается

**Граница с источником данных.** Сервер не знает, как устроена физика машины: источник пишет
только 23 физических показателя в порядке `METRIC_ORDER` через `SnapshotWriter`. Производные
показатели, статус, светофор и события считает сервер. Подмена заглушки на симулятор этапа 5 -
это одна строка в `engine.ts` (параметр `source`).

**Горячий путь.** При 60 машинах и ускорении x60 это 3600 кадров и около 108 000 значений
в секунду, поэтому в пути записи нет ни аллокаций на значение, ни строковых ключей:
нормативы разобраны в таблицу по индексам при старте, индексы бакетов считаются один раз
на кадр, значения лежат в типизированных массивах.

**Виртуальное время.** Один таймер на 100 мс выполняет `timeScale / 10` шагов. Шаги не
пропускаются: неотработанный долг виден в `/api/health` как `clock.lagSeconds`.

## Замеры

60 машин, ускорение x60, мера хаоса UGLY: отставания часов нет, генерация занимает 6-7%
реального времени, буферы хранилища 172 МБ, RSS процесса 290 МБ, поток websocket около
360 КБ/с при четырех тиках в секунду. Предыстория 12 часов на 3 машины генерируется
за 0,7 с при старте; предыстория новых машин при расширении парка до 60 идет в фоне
порциями по 25 мс, чтобы сервер продолжал отвечать.
